SETUP                                                     *pi-x-ide-setup*

With lazy.nvim:
>
  {
    "balaenis/pi-x-ide",
    build = function(plugin)
        vim.opt.rtp:prepend(plugin.dir .. "/ide-plugins/nvim")
        require("pi_x_ide.download").run({ refresh = true })
    end,
    init = function(plugin)
        vim.opt.rtp:prepend(plugin.dir .. "/ide-plugins/nvim")
    end,
    main = "pi_x_ide",
    opts = {
        keymap = "<leader>aa",
    },
  }
<

Note: The `init` block manually adds the `ide-plugins/nvim/` subdirectory to the runtime
path. This avoids a Lua module resolution issue with lazy.nvim's `rtp` option
on some versions. Plugin options are passed through lazy.nvim's recommended
`opts` field. The optional `build` hook uses the bundled sidecar binary when
present; otherwise it checks the GitHub Release asset digest on install/update
and downloads only when the cached binary is missing or stale.

With native packages, clone the repository into a `pack/*/start` directory and
add the `ide-plugins/nvim` subdirectory to your runtime path before setup:
>
  set runtimepath+=/path/to/pi-x-ide/ide-plugins/nvim
  lua require("pi_x_ide").setup({ keymap = "<leader>pa" })
<

The plugin starts a sidecar process that communicates Pi's IDE context.  On first
start the plugin downloads a standalone binary for your platform (Linux / macOS /
Windows, x64 or arm64).  If the download fails, or no binary matches your
platform, the plugin falls back to `node <plugin-root>/bin/pi-x-ide-nvim-
sidecar.cjs`, which requires Node.js on PATH.

Downloaded binaries are cached under `stdpath("cache")/pi-x-ide/` and reused on
subsequent starts.  The optional lazy.nvim build hook uses the bundled binary
when present; otherwise it checks the release digest on install and update,
downloading only when the cached binary is missing or stale.

===============================================================================
COMMANDS                                               *pi-x-ide-commands*

:PiXIdeStart
    Start the Neovim sidecar.

:PiXIdeStop
    Stop the Neovim sidecar and remove its lock file.

:PiXIdeStatus
    Show whether the sidecar is running.

:PiXIdeAttach
    Attach the current file or selection to connected Pi clients. In Pi this
    inserts an `@relative/path#Lx-Ly` reference, matching the VS Code attach flow.

===============================================================================
OPTIONS                                                 *pi-x-ide-options*

Pass options to `require("pi_x_ide").setup({ ... })`.

`enabled` (boolean, default true)
    Start the sidecar during setup.

`sidecar_cmd` (string[]|nil)
    Command used to start the sidecar. Defaults to the platform binary
    (`pi-x-ide-nvim-sidecar-{platform}`) or falls back to:
    `node <plugin-root>/bin/pi-x-ide-nvim-sidecar.cjs`.

`debounce_ms` (number, default 150)
    Delay for high-frequency cursor and text-change updates.

`keymap` (string|nil)
    Optional normal/visual mode mapping for `:PiXIdeAttach` behavior.

`workspace_folders` (string[]|nil)
    Explicit workspace folder list. Defaults to current working directory plus
    active LSP workspace folders when available.

===============================================================================
TROUBLESHOOTING                                 *pi-x-ide-troubleshooting*

No `nvim-*.lock` file appears under `~/.pi/pi-x-ide/`:
    Run `:PiXIdeStatus`.  The binary is cached at `stdpath("cache")/pi-x-ide/`
    or bundled at `<plugin>/ide-plugins/nvim/bin/`.  If neither is found, the plugin
    auto-downloads from GitHub Releases on first start (requires curl or wget).
    Use `sidecar_cmd` to set an explicit Node.js command as a fallback.

Pi shows no IDE connection:
    Start Pi in the same project directory and run `/ide auto`. If the project
    layout is unusual, run `/ide` and choose the Neovim connection manually.

The keymap does not work:
    Choose a different `keymap` value in setup. The plugin does not install a
    default keymap to avoid conflicts with existing Neovim configs.

Selection is not attached:
    Use visual mode and invoke the configured keymap or `:PiXIdeAttach`. The
    plugin sends file context for normal cursor movement and selection context
    for active or recently completed visual selections.

module 'pi_x_ide' not found with lazy.nvim:
    Some lazy.nvim versions fail to update Lua's package.path when `rtp` is
    used. Replace `rtp = "ide-plugins/nvim"` with an `init` block that prepends the path:
>
      init = function()
        vim.opt.rtp:prepend(vim.fn.stdpath("data") .. "/lazy/pi-x-ide/ide-plugins/nvim")
      end,
<
